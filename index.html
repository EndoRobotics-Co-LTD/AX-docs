AI 에이전트란?

1.1 AI 활용 철학

이미 우리는 AI를 많은 곳에 사용하고 있습니다.
여기저기서 많은 것들을 듣고 배운 우리는, AI에게 우리의 수많은 맥락을 이해시키며 AI를 사용하고 있습니다.

거기서 좀더 나아가신 분들은, 이제 그 AI에게 각자가 원하는 도구를 만들게 시키고 계실 겁니다.
평소에 상상만 해오던 — 정말 나만을 위한, 세상에 하나뿐인 도구.

여기서 질문.

과연 본질은 그 AI가 만든 도구에 있을까요?
아니면 여러분이 수많은 시간과 노고를 쏟아부은 AI 그 자체에 있을까요?

아래 하나의 예시를 들어보겠습니다.

평소에 시료의 재고 및 히스토리 관리를 해오던 ‘원석이’가 있습니다.
매번 스스로의 기억에 의존해오던 원석이는 AI를 만나고, 그 AI에게 — 우리가 어떤 시료들을 관리중에 있고, 그 시료들로 어떤 작업을 하고, 히스토리를 어떻게 관리해야 하면 좋을지 — 수없이 대화를 나누었습니다.

그러던 어느 날, AI로 코딩을 해볼 수도 있겠다는 생각에 평소에 생각만 해오던 시료 관리 대시보드를 만들기로 합니다.
원석이는 일주일동안 열심히 AI와 고군분투하며, 결국 원하던 형태의 시료 관리 대시보드를 만들어내었습니다.

이 과정에서 원석이는 정말 많은 것을 배웠을 겁니다. 평생 안해본 웹개발을 해보고, 상상만 해오던 도구를 만들어보며 많은 성장을 했을 겁니다.

하지만 여기까지 오신 분들이 한분이라도 계신다면, 전 반드시 이 질문을 드리고 싶습니다.

과연 원석이가 가지고 있던 문제는 대시보드만이 해결할 수 있었을까요?
그 대시보드를 만들기 위해 열심히 원석이의 경험치를 받아먹은 그 AI가, 그냥 그 시료에 대한 모든 재고와 히스토리를 기억해줄 수 있지 않을까요?
그리고 필요한 순간, 원하는 형태로 나에게 답변해줄 수 있지 않을까요?
물론 대시보드가 나쁜 솔루션은 아닙니다만,
저희 각자가 자신만의 굳건한 철학을 세우지 않는다면 저희는 AI의 매력에 그저 이끌려갈 수도 있습니다.
이 제언을 드리며 강의를 시작합니다.

1.2 AI 서비스 종류

같은 Claude라도 서비스 형태가 여럿입니다. 각자 목적/취향에 따라 선택합니다.

서비스설명적합
Claude.ai일반 사용자용 채팅 (웹/데스크톱/모바일)대화·검색·문서 초안
Cowork데스크톱 AI 에이전트 — 목표만 주면 알아서 계획/실행 (단, 기초적인 하네스만 사용 가능)비개발 지식업무 · 속도·편의
Claude Code터미널/IDE 코딩 에이전트 — 무엇을/어떻게 할지 직접 명시 (하네스도 직접 설계, Full-Custom)코딩·정밀·복잡 워크플로우
(Claude API)개발자가 자기 앱에 Claude를 넣는 길.개발자용
Cowork · Claude Code = 내 PC의 ‘로컬 에이전트’ — 브라우저 채팅(Claude.ai)과 달리, 내 로컬 PC에서 직접 내 파일·폴더를 열고 다루며 작업합니다.

1.3 하네스(Harness)란?

아무런 커스텀도 되어 있지 않은 AI는 ‘일반적인 사고’를 합니다.
비유하자면 — 대학교 자율전공학부 신입생입니다. 단, 학교는 서울대. 즉 아주 똑똑하지만 아직 전공이 없는 상태죠.

그래서 이 학생은 뭘 제일 잘할까요? 국·영·수·탐 전부 ‘적당히’ 잘합니다. 딱히 뾰족한 분야는 없습니다.

그런데 2학년이 되면 전공을 고릅니다 — 기계공학, 신소재공학, 영문학….
그 커리큘럼을 밟고 졸업하면, 이제 자신만의 전공 분야가 하나 생깁니다.

이게 바로 하네스입니다.
인터넷에 떠다니는 화려한 용어에 휘둘릴 필요 없습니다. — 똑똑하기만 하던 AI에게 특정 ‘전공 커리큘럼’을 밟게 해, 더 날카로운 AI로 만드는 것. 그것이 하네스입니다.

그럼 ‘도구’와 ‘AI’는 뭐가 다를까?

신뢰도이유
도구버그만 없으면 100% 신뢰늘 같은 입력 → 같은 결과 (계산기·엑셀)
AI100% 신뢰 불가확률 모델이라 같은 질문에도 답이 달라질 수 있음
AI + 하네스신뢰 격차를 좁힘‘전공’을 시켜 더 일관되고 정확하게

결국, 내 목적에 따라 고르는 것

내 상황선택
신뢰도는 덜 중요하고, 효율성이 우선이다AI
어느 정도의 신뢰성 + 효율성이 둘 다 중요하다AI + 하네스
100% 신뢰도가 반드시 필요하다검증된 도구

1.4 하네스의 구조

하네스는 크게 3층으로 쌓입니다. 위에서 아래로 갈수록 AI를 더 강하게 묶어 줍니다.

자체 메모리 — 하네스가 없어도 기본 동작

아무것도 붙이지 않아도, AI는 대화 속에서 나눈 맥락을 기억하며 동작합니다. 모든 것의 출발점입니다.

SOFT 하네스 — ‘권유’로 방향을 잡아줌

  1. 맥락 + 지시 — 무엇을·어떻게 할지 글로 알려줌 (예: 프롬프트, CLAUDE.md 등)
  2. 외부 도구 연결 — 쓸 수 있는 도구·데이터를 붙여줌 (예: SKILL, Command, MCP, 커넥터, 플러그인 등)

HARD 하네스 — ‘강제’로 못 벗어나게 함

  1. 시스템 명령 — 정해진 절차를 강제 실행 (예: 루프, 훅 등)
  2. 환경설정 — 할 수 있는 것/없는 것을 제한 (예: 에이전트 권한 등)

SOFT vs HARD

SOFT는 모델이 ‘읽고 따라주길’ 기대 — 어길 수 있음. HARD는 코드가 ‘강제’ — 모델 의도와 무관하게 못 어김.

성격무엇믿을 수 있나?
SOFT맥락·지시, 외부 도구 연결모델이 따라주길 기대 → 어길 수 있음
HARD시스템 명령(루프·훅), 권한·샌드박스코드가 실행 직전 강제 → 못 어김
결론 — 신뢰는 SOFT(지시)가 아니라 HARD(권한·훅)에서 나온다.

[참고] 생태계 용어 정리

자체 메모리 · 생성 정보대화에서 기억한 맥락 + 학습으로 아는 지식빠르지만 모르는·최신 정보엔 약함 (환각 위험)

원격(Remote)클라우드 서버에서 실행설치 없이 URL로 연결, 데이터는 외부로 나감

커넥터MCP 서버를 Claude.ai 계정에 자동 연결할 수 있게 만든 것MCP 서버는 원래 프로젝트 단위 연결 → 커넥터는 계정 단위라 모든 프로젝트에 자동 연결
플러그인여러 하네스(커맨드·스킬·훅·MCP·서브에이전트)를 묶은 패키지마켓플레이스에서 다운로드

1.5 기초 사용법 — Cowork (비개발자용)

Windows 기준 · 계정은 전사 팀플랜으로 발급 완료 → 바로 설치부터.

Cowork 설치

  1. 다운로드: claude.com/download → Claude Setup.exe 실행 → 설치.
  2. Claude Desktop 실행 → 회사 계정으로 로그인(브라우저 인증 “Authorize”).
  3. 좌측/상단에서 Cowork 모드 선택.
  4. 첫 작업 예: “내 다운로드 폴더의 PDF를 날짜별 폴더로 정리해줘.” → Claude가 계획(Plan) 제시.
  5. 폴더 접근 권한 “Allow”, 실행 모드는 “Ask before acting”(각 단계 확인) 권장 → 실행.
막히는 지점: 시스템 폴더(C:\Windows 등)는 차단 — 개인 폴더만. · 작업 중 Claude Desktop은 켜둬야 함. · 첫 작업은 작고 명확하게, 중요 파일은 백업.

다만 Cowork는 기초적인 SOFT 하네스만 쓸 수 있어 — 나만의 Full-custom 하네스 설계는 어렵습니다.

1.6 기초 사용법 — Claude Code (개발자용)

Windows 기준 · 터미널 기반. 사전 도구(Git)·환경변수부터 첫 실행까지.

A. 사전 준비 — Git 설치 & 환경변수

  1. Git for Windows 설치: git-scm.com/download/win → 내려받아 실행 → 기본 옵션 그대로(“Add to PATH” 유지) 설치. 확인: git --version
  2. 환경변수(PATH) — 설치 후 git·claude가 “인식 안 됨”이면:
    ① Win+X → 시스템 → 고급 시스템 설정 → 환경 변수
    ② 사용자 변수의 Path → 편집 → 새로 만들기 → %USERPROFILE%\.local\bin 추가(Claude 설치 경로)
    ③ 확인 → PowerShell 재시작

B. Claude Code 설치

  1. 시작메뉴 → PowerShell 실행(관리자 권한 불필요. 프롬프트 좌측이 PS C:\ 인지 확인).
  2. 설치 (PowerShell 한 줄): 
    irm https://claude.ai/install.ps1 | iex
  3. 확인: claude --version
  4. 로그인: claude 입력 → 브라우저 열림 → 회사 계정 “Authorize”.

C. 자주 발생하는 오류 & 해결

① claude 명령어가 인식되지 않을 때 — 터미널을 재시작해도 'claude'은(는) 내부 또는 외부 명령…으로 인식되지 않습니다가 뜨면, PATH를 직접 추가합니다.

[Environment]::SetEnvironmentVariable("PATH", "$env:PATH;$env:USERPROFILE\.local\bin", [EnvironmentVariableTarget]::User)

실행 후 PowerShell 재시작 → claude --version 재확인.

② PowerShell 스크립트 실행 차단 오류 — 이 시스템에서 스크립트를 실행할 수 없습니다…가 뜨면 실행 정책을 풀어줍니다.

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

③ Git 환경변수(PATH)가 설정 안 됐을 때 — 설치했는데 git --version이 'git'은(는) … 인식되지 않습니다로 실패하면, 설치 시 “Add to PATH”가 빠진 것입니다. Git 경로를 PATH에 추가합니다.

[Environment]::SetEnvironmentVariable("PATH", "$env:PATH;C:\Program Files\Git\cmd", [EnvironmentVariableTarget]::User)

실행 후 PowerShell 재시작 → git --version 재확인. (또는 Git for Windows를 “Add to PATH” 옵션으로 재설치)

그 밖에: irm 인식 안 됨 → CMD가 아닌 PowerShell에서 실행 · 로그인 창 안 뜸 → 팝업·방화벽 허용.

D. Claude의 물리 구조 (전역 · 프로젝트 · 세션)

Claude Code의 설정은 대부분 약속된 위치의 파일입니다. 크게 전역(모든 프로젝트 공통)과 프로젝트(이 폴더 전용)로 나뉩니다.

전역 — 모든 프로젝트 공통 (~/.claude/)

~/.claude/
├─ CLAUDE.md          # 전역 메모리(모든 프로젝트에 적용)
├─ settings.json      # 전역 설정(권한·훅 등)
├─ agents/  skills/  commands/  plugins/
└─ projects/<프로젝트>/*.jsonl   # 세션 대화 기록(트랜스크립트)
~/.claude.json        # 사용자 설정 · 프로젝트 이력

프로젝트 내부 — 이 폴더 전용 (<프로젝트>/.claude/)

<프로젝트 루트>/
├─ CLAUDE.md          # 이 프로젝트 메모리(시작 시 자동 로드)
├─ .mcp.json          # 이 프로젝트 MCP 서버
└─ .claude/
   ├─ settings.json   # 권한·훅·MCP 활성
   └─ agents/  skills/  commands/

단위 개념 — 프로젝트 vs 세션

단위뜻특징
프로젝트(Project)작업하는 폴더 하나 = 하나의 맥락 공간CLAUDE.md·.mcp.json·.claude/가 그 폴더에 종속 → 폴더마다 설정·맥락이 다름
세션(Session)claude를 켜서 끌 때까지의 한 번의 대화기록은 ~/.claude/projects/<프로젝트>/*.jsonl에 저장 · 새 세션이면 컨텍스트 초기화(영구 기억은 CLAUDE.md/메모리에)

E. 첫 실행

작업하고 싶은 폴더로 가서, 그 위치에서 PowerShell을 열고 claude를 실행하면 끝!

claude
> 이 폴더의 .txt 파일들을 정리해줄래?
여기까지가 설치 & 첫 실행입니다. CLAUDE.md·권한·MCP·훅 등으로 하네스를 직접 씌우는 방법은 이번 강의에서는 다루지 않고 2강에서 진행합니다.
